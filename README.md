# Squadron Dashboard

A self-hosted screen for a squadron/unit room: clock, weather, news headlines, a top-5 leaderboard, events, and socials — plus a mobile-friendly edit page. Built for an Air Cadets squadron originally, but generic enough for any club, unit, or common room.

## Quickstart (one command)

On the Raspberry Pi, with internet connected, this one command clones the repo, installs everything it needs, sets up passwordless auto-shutdown, and installs a systemd service so the dashboard starts automatically on every boot and restarts itself if it ever crashes:

```bash
git clone https://github.com/<your-username>/squadron-dashboard.git && cd squadron-dashboard && ./setup.sh
```

That's it — the dashboard is now running at `http://localhost:3000` and will keep running across reboots and crashes with no further steps.

To update later after you've made changes and pushed them to GitHub:

```bash
cd squadron-dashboard && git pull && ./setup.sh
```

(`setup.sh` is safe to re-run any time — it skips steps that are already done.)

### Putting this on GitHub yourself

I can't push to GitHub directly, but getting this folder into a repo takes a couple of minutes:

1. Go to [github.com/new](https://github.com/new), create a repository called `squadron-dashboard` (public or private, your choice).
2. On your own computer, in this folder, run:
   ```bash
   git init
   git add .
   git commit -m "Initial squadron dashboard"
   git branch -M main
   git remote add origin https://github.com/<your-username>/squadron-dashboard.git
   git push -u origin main
   ```
3. Use the `git clone ...` command above on the Pi from then on.

Because `node_modules` isn't committed to the repo (standard practice — it's regenerated by `npm install`), the Pi needs internet for this one clone-and-setup step. After that, everything runs entirely offline — the dependencies live in `node_modules` on disk, not in the repo, and the dashboard never needs to reach the internet again except to fetch live weather/news/leaderboard data.

## What setup.sh does for you

- Installs Node.js if it isn't already present
- Runs `npm install` to pull in `express`, `node-fetch`, and `rss-parser`
- Grants the dashboard passwordless permission to run `shutdown` (needed for auto-off — see below)
- Installs and enables a systemd service (`squadron-dashboard.service`) so the dashboard starts on boot and restarts itself on crash

## Manual setup (if you'd rather not use setup.sh)

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
cd squadron-dashboard
npm install
npm start
```

You'll see something like:

```
Squadron dashboard running:
  Display:  http://localhost:3000
  Edit (from any phone/laptop on the network): http://<this-pi's-IP>:3000/edit
```

Find the Pi's IP with `hostname -I` if you need it.

## Kiosk autostart

Point the Pi's browser (Chromium in kiosk mode works well) at `http://localhost:3000`:

```bash
chromium-browser --kiosk --noerrdialogs --disable-infobars http://localhost:3000
```

Add that command to your desktop environment's autostart (e.g. `~/.config/lxsession/LXDE-pi/autostart` on Raspberry Pi OS) so it launches automatically after boot, alongside the `setup.sh`-installed service that keeps the server itself running.

## Editing content from any device

From any phone or laptop on the same Wi-Fi as the Pi, go to:

```
http://<pi's-IP-address>:3000/edit
```

From there you can update:
- Squadron/unit name and weather location
- The Google Sheets CSV link for the leaderboard
- The "more events" QR link
- The error-report QR link (shown if a panel fails to load — leave blank to disable it)
- The Instagram widget embed URL (get one free from a service like sociablekit.com or elfsight.com)
- Events list
- Social media links (Facebook, X)

News is fixed to BBC News and isn't editable from this page. Changes made here are picked up by the display within about 10 seconds.

## Connecting your leaderboard

In your points tracker Google Sheet: **File > Share > Publish to web**, choose the specific sheet/tab with names and points, pick **CSV**, and paste that link into the edit page's "Leaderboard Google Sheets CSV link" field.

The dashboard expects a header row with a column containing "name" and a column containing "point" (case-insensitive) — it works with most simple points-tracker layouts as long as those two columns exist. If your sheet has a pre-ranked "LEADERBOARD" section above a messier full list, the parser looks for a row with both "rank" and "name" columns first and reads straight down from there, keeping your sheet's own tie-breaking order.

## Events

There's no universal "events" API to pull from, so events are entered by hand on the `/edit` page — quick to update from a phone.

## Auto shutdown

The dashboard automatically powers the Pi off 2 hours 45 minutes after the server starts (handy if it's normally switched on manually and then forgotten about). `setup.sh` configures the passwordless permission this needs automatically. If you used the manual setup instead, add it yourself:

```bash
sudo visudo
```

Add this line at the bottom (replace `pi` with whichever user runs the server):

```
pi ALL=(ALL) NOPASSWD: /sbin/shutdown
```

Without this step, the server still runs fine — you'll just see a warning in the console and the Pi won't power itself off automatically.

## Power cuts and corrupted settings

The Pi may get switched off at the wall at any point, with no warning. The app is built around that:

- Settings are never held only in memory — every page load and every save reads and writes straight to `data.json` on disk.
- Saves are atomic (write to a temp file, then rename it into place), so a mid-write power cut can never leave `data.json` half-written or corrupted.
- A redundant copy is kept at `data.backup.json` on every save. If `data.json` is ever found corrupted on boot, the server automatically restores it from the backup.
- If both files are somehow lost, the server falls back to sensible built-in defaults rather than crashing, and immediately writes those back to disk.

No manual recovery steps needed — just power it back on.

## Checking on it later

```bash
sudo systemctl status squadron-dashboard   # is it running?
journalctl -u squadron-dashboard -f        # live logs
sudo systemctl restart squadron-dashboard  # restart manually if needed
```
